# Система игровых сценариев

## Статус

Первая версия реализована: общий registry, context, runner, result и builder; два режима выполнения; отчёты; теги; миграция прежних visual-тестов и первая матрица взаимодействий. Разделы ниже фиксируют архитектуру и правила её дальнейшего расширения.

## Цель

Создать единый детерминированный конструктор сценариев, которым агенты проверяют игровую механику и визуальный результат без копирования setup-кода. Сценарий должен описывать только начальное состояние, действия, контрольные точки и ожидаемый результат.

## Основные правила

- Один сценарий проверяет одно конкретное поведение и имеет стабильное имя.
- Все сценарии собираются через общий API; цепочки `if (scenarioName.equals(...))` в игровом коде не расширяются.
- Случайность задаётся seed, время продвигается фиксированными тиками, объекты получают стабильные идентификаторы внутри сценария.
- Механика проверяется assertions и state dump. Скриншот не заменяет проверку состояния.
- Скриншот добавляется только когда важен видимый результат.
- Сценарии используют настоящую игровую логику. Копировать в тест расчёт урона, столкновений или наведения нельзя.
- Тестовый код не должен влиять на обычный запуск игры без параметра сценария.

## Архитектура

```text
ScenarioRegistry
    хранит сценарии и выбирает их по имени или тегам

ScenarioDefinition / ScenarioBuilder
    seed, setup, действия, контрольные точки, assertions, снимки, теги

ScenarioContext
    доступ к PlayState, времени и объектам по стабильным id

ScenarioRunner
    создаёт изолированный мир, выполняет фиксированные тики и проверки

ScenarioAssertion
    здоровье, удаление, позиция, количество объектов, очки, опыт и т. п.

ScenarioReport
    PASS/FAIL, значения до/после, ошибки, длительность и пути снимков
```

Пример желаемого развития API:

```java
scenario("rocket-hits-enemy")
        .tags("rocket", "collision", "enemy-ship", "visual")
        .seed(42L)
        .player("player").at(640f, 360f)
        .enemyShip("target").at(820f, 420f).health(3)
        .rocket("rocket").from("player").target("target")
        .at(2.0f).expectHealth("target", 2)
        .expectRemoved("rocket")
        .capture("impact");
```

Текущая первая версия предоставляет более компактные универсальные методы `setup`, `tick`, `checkAt` и `captureAt`. Специализированные fluent-методы из примера добавляются только после появления реального повторения в нескольких сценариях.

## Два режима выполнения

### Logic

- Выполняет фиксированные тики максимально быстро, без ожидания реального времени.
- Проверяет столкновения, урон, выбор цели, награды, удаление и создание объектов.
- Не создаёт PNG, если визуальная проверка не нужна.

### Visual

- Использует тот же setup и те же assertions.
- Отрисовывает выбранные контрольные точки и сохраняет PNG.
- Агент обязан открыть и фактически осмотреть полученный снимок.

Один сценарий может поддерживать оба режима; setup и ожидания не дублируются.

## Команды и артефакты

Команды:

```bash
./gradlew desktop:runScenario -Pscenario=rocket-hits-enemy
./gradlew desktop:scenarioSuite -PscenarioTags=rocket,collision
./gradlew desktop:scenarioSuite
```

Результаты каждого запуска:

```text
build/scenarios/<scenario>/result.txt
build/scenarios/<scenario>/result.json
build/scenarios/<scenario>/<checkpoint>.png
```

Провал assertion должен завершать Gradle-задачу ненулевым кодом. Отчёт создаётся и при успехе, и при ошибке.

## Этапы реализации

Этапы 1–4 выполнены. Этап 5 остаётся направлением развития и выполняется только при подтверждённой пользе.

### 1. Каркас

- Реализовать registry, context, runner, result и минимальный builder.
- Обеспечить изолированную инициализацию одного PlayState без случайных мировых объектов.
- Добавить стабильный seed, фиксированные тики и поиск объектов по scenario id.
- Сохранить временную совместимость с `-PvisualTest`.

### 2. Миграция текущих visual-тестов

- Перенести `straight`, `diagonal`, `side`, `turnleft`, `turnright`, `coast`, `rocket` и `enemy-smoke` в registry.
- Удалить выбор сценариев из `Player` и `PlayState`; управление передать runner/actions.
- Сохранить автоматическое создание и завершение PNG-снимков.

### 3. Assertions, отчёты и выборочный запуск

- Добавить общие проверки здоровья, удаления, позиции, количества объектов, очков и опыта.
- Добавить текстовый и JSON-отчёты.
- Добавить теги и запуск одного сценария, набора тегов или полного suite.

### 4. Первая матрица взаимодействий

- `bullet-hits-asteroid`
- `rocket-hits-enemy`
- `enemy-shoots-player`
- `shield-blocks-collision`
- `enemy-destroyed-rewards-player`

Каждый сценарий обязан проверять состояние. PNG нужен только для визуально значимых контрольных точек.

### 5. Ускорение и расширение

- Переиспользовать один процесс для suite, если изоляция мира доказана тестами.
- Добавлять builder-методы только после появления повторения.
- При необходимости выделять чистую игровую логику в обычные unit-тесты; scenario runner не заменяет unit-тесты формул и алгоритмов.

## Критерии готовности первой версии

- Пять сценариев матрицы проходят детерминированно при повторных запусках.
- Сценарии не содержат скопированной игровой логики.
- Один и тот же setup используется в logic- и visual-режимах.
- По имени и тегам запускаются только нужные сценарии.
- Ошибка сообщает сценарий, assertion, ожидаемое и фактическое значение.
- Скриншоты и отчёты находятся по предсказуемым путям в `build/scenarios/`.
- Обычный `./gradlew desktop:run` не меняет поведение.

## Правило расширения

При добавлении или изменении наблюдаемой механики агент сначала ищет существующий сценарий и расширяет его, если ответственность остаётся прежней. Новый сценарий добавляется, когда появляется отдельное поведение или отдельный путь взаимодействия. Для внутренних рефакторингов без изменения поведения новые сценарии не требуются.

## Зафиксированные боевые контракты

- `EnemyShip` имеет 3 здоровья, `OrkAsteroid` — 2; обычные астероиды уничтожаются одним попаданием независимо от размера.
- Пуля игрока наносит 1 урон, ракета — 2 прямого урона и 1 урон другим врагам в радиусе 60. Игрок не получает урон от взрыва своей ракеты.
- Награда начисляется только за уничтожение: `EnemyShip` — 25 очков и опыта, `OrkAsteroid` — 10, конечный маленький обычный астероид — 5. Разделение большой и средней стадий награды не даёт.
- Вражеская пуля игнорирует владельца, исчезает при столкновении с другим врагом без нанесения ему урона и продолжает существовать после смерти стрелка.
- Ракета ищет ближайшую цель без приоритета типа в радиусе 1200. После потери цели она продолжает полёт и поиск в течение 3 секунд, затем исчезает; несколько ракет могут выбрать одну цель.
