# Сохранение игры

## Пользовательский flow

- При первом запуске меню показывает `НОВАЯ ИГРА`, `НАСТРОЙКИ`, `ВЫХОД`.
- После первого автосохранения появляется `ПРОДОЛЖИТЬ`.
- Игра сохраняется при выходе из gameplay в паузу, меню или при завершении приложения.
- `НОВАЯ ИГРА` удаляет основной файл, временный файл и резервную копию.
- Scenario-mode никогда не читает и не перезаписывает пользовательский слот.

Файл хранится через `Gdx.files.local` по пути `saves/session.json`. Перед заменой
валидный предыдущий файл переносится в `session.json.bak`. Если основной JSON
повреждён, загрузка автоматически пробует backup.

## Контракт формата

Текущая версия — `1`. `GameSaveData` содержит только data-only поля:

- score, high score, level, время сессии и таймер авторакеты;
- позицию, скорость и направление игрока;
- XP и числовые параметры progression;
- идентификаторы выбранных улучшений.

Не сохраняются transient-объекты: летящие снаряды, частицы, активные враги и
случайная форма астероидов. При продолжении мир регенерируется вокруг сохранённой
позиции игрока. Runtime checkpoint для сценариев остаётся отдельным shallow
механизмом и не используется как файловый формат.

## Правила расширения

1. Не сериализовать entity, pool, listener, `Runnable` или `GameObject` напрямую.
2. Новые долговечные поля добавлять в `GameSaveData` и оба направления
   `GameSessionSaveMapper`.
3. Несовместимое изменение повышает `CURRENT_VERSION` и требует явной миграции.
4. После изменения запускать `persistent-save-round-trip` и полный logic-набор.
5. Изменение меню дополнительно проверять визуально и кликами.
